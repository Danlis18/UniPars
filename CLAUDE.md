# UniPars

Платформа взаємодопомоги студентів ЛНУ: предмети, завдання, подання з модерацією, форум, повідомлення, регенерація звітів.
Стек: React + Vite (`frontend/`), FastAPI (`backend/`), Supabase Postgres + RLS (`supabase/migrations/`), Railway.
Рівень якості — продукт стартапу: продакшн-рішення за замовчуванням.

## Процес
- Одна задача = одна гілка = один PR. Без прямих комітів у `main`.
- Назви гілок: `feat/…`, `fix/…`, `chore/…`, `ops/…`, `perf/…`.
- Перед PR: `python -m pytest -q` (у `backend/`) і `npx playwright test` (у `frontend/`). CI має бути зеленим.
- Без force-push. Злиття тільки після підтвердження власника.
- Файли, які правлять кілька людей (міграції, `services/billing.py`, `services/access.py`, `app/App.jsx`, `components/Layout.jsx`), — лише точкові зміни; власники в `.github/CODEOWNERS`.

## База
- Тільки нові міграції, які можна запускати повторно (`if not exists`, `drop policy if exists`). Застосовані не змінювати.
- Тести працюють лише в демо-режимі (`APP_MODE=demo`, база в пам'яті) і ніколи не чіпають прод.
- Нова таблиця або колонка — додати її в перевірку `/api/health?deep=1` (`backend/app/main.py`) і в `scripts/smoke_prod.py`.

## Секрети
- Тільки змінні середовища (`backend/app/core/config.py`, `VITE_*` для фронтенду). `.env` — у `.gitignore`.
- Значення ключів не писати в код, логи, чат, коміти й PR.
- `/api/health` показує лише так/ні, без значень.

## Гроші
- Усе тільки через `backend/app/services/billing.py`.
- Кожна зміна балансу — запис у `credit_ledger`; баланс має збігатися із сумою журналу.
- Вебхук без правильного підпису відхиляється. Успішний платіж ніколи не понижується в статусі.
- Тестовий режим оплат у проді — лише для адмінів.

## Економія токенів
- Відповідати коротко, без вступів.
- Спершу grep, а не читання цілих файлів; читати лише потрібні рядки.
- Точкові правки через Edit, без переписування файлів.
